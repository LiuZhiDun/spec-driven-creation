# Spec模板（Creative Brief）

> 创作前填写，定义"做什么、为谁做、做到什么程度算合格"。
> 借鉴：Creative Brief、Content Brief、Definition of Done。
> 填写说明：每个字段都要具体，禁止"随便""都行""大概"这类模糊表述。
> 本模板为通用空模板，项目特有的配置（创作风格、合规规则等）在 cwd 的 `.sdc/` 目录中定义。

## 1. 项目概述

**主题：** （一句话说清楚这篇作品讲什么）

**核心问题：** （这篇作品要回答的核心问题是什么？）

**一句话概括：** （如果只能用一句话向别人介绍这篇作品，你会怎么说？）

**背景与动机：** （为什么要做这个？是什么触发了这个创作需求？）

## 2. 目标读者

**主要读者：** （主要给谁看？描述他们的特征：知识水平、当前状态、核心痛点）

**读者期望获得：** （他们读完后期望得到什么？新视角？情感共鸣？实用方法？还是其他？）

**读者不想要：** （他们不想要什么？说教？鸡汤？太学术？太浅？）

## 9. 验收标准（Definition of Done）

> 以下标准必须全部满足，作品才算"做完"。Harness审查时逐项验证。
> 项目特有的检查项定义在 `.sdc/harness-checklist.md` 中。

**必须满足（阻断级）：**
- [ ] 无隐私/合规违规（参考 `.sdc/compliance.md`）
- [ ] 无内容边界违规（参考 `.sdc/compliance.md`）
- [ ] 无版权侵权风险
- [ ] 所有引用标注来源，文末有完整参考资料列表
- [ ] 所有数据可查证，口径清晰
- [ ] 主视角与项目配置一致，角色使用一致
- [ ] 符合Spec定义的主题、结构、篇幅

**应该满足（重要级）：**
- [ ] 符合项目创作风格规范（参考 `.sdc/creative-style.md`）
- [ ] 开场/结尾符合项目风格规范
- [ ] 每个观点有具体场景或比喻支撑
- [ ] 风格比例符合Spec目标
- [ ] 无项目禁忌清单中的内容
- [ ] （视频脚本）每段旁白有对应画面，无纯旁白段落
- [ ] （视频脚本）脚注/参考资料在视频中呈现

**可以满足（建议级）：**
- [ ] 有至少一个翻转点（"啊哈时刻"）
- [ ] 有至少一处幽默/轻松调剂
- [ ] 有留白和停顿

## Spec自检验证

填写完成后，自问：

> "拿着这份Spec，另一个创作者能产出符合预期的作品吗？"

- 如果能 → Spec通过，可以进入素材准备阶段
- 如果不能 → Spec不够具体，需要补充模糊字段后再开始
